# AI for AI — AI가 직접 가르치는 AI 교육 프로그램

> Claude Code의 Skills 기능을 활용하여, AI 튜터가 학습자와 1:1 대화하며  
> LLM/AI Agent 개념을 가르치는 교육 프로그램입니다.

---

## 이 프로그램은 무엇인가

교육 커리큘럼 자체를 Claude Code의 Skill로 구현한 프로그램입니다. 학습자가 터미널에서 명령어를 입력하면 AI 튜터가 대화를 시작합니다. 슬라이드도, 영상도 없이 — AI가 직접 질문하고, 설명하고, 이해도를 확인합니다.

```
┌──────────────────────────────────────────────────────┐
│  학습자 터미널                                         │
│                                                      │
│  $ claude                                            │
│  > /start             ← 진단 대화 시작                 │
│  > /module1           ← Module 1 Skill 실행           │
│  > /explore RAG       ← 탐색 모드로 키워드 탐색        │
│                                                      │
│  Claude가 SKILL.md를 읽고 AI 튜터로 작동               │
└──────────────────────────────────────────────────────┘
```

이 문서는 프로그램의 사용법이 아니라, **이 프로그램을 설계하면서 내린 결정들과 그 근거**를 정리한 것입니다.

---

---

## 핵심 설계 결정

이 프로그램을 만들면서 가장 많이 고민한 부분은 두 가지였습니다:

1. AI 튜터가 교육을 "어떻게" 이끌어갈 것인가 → **프로그램 설계 원칙**
2. 학습자를 모르는 상태에서 어떻게 맞춤형 교육을 시작할 것인가 → **진단 대화 설계**

## 1. 프로그램 설계 원칙

---

### 1-1. "What은 고정, How는 자유" 원칙

가장 근본적인 설계 결정입니다.

교육 프로그램을 AI에게 맡길 때 가장 큰 리스크는 AI가 학습 목표를 벗어나거나, 반대로 스크립트를 그대로 읽는 것처럼 경직되는 것입니다. 이 둘 사이의 균형을 잡기 위해 **"무엇을 가르칠 것인가(What)"** 와 **"어떻게 이끌 것인가(How)"** 를 분리했습니다.

```
┌─────────────────────────────────────────────────────────┐
│                    교육 시스템 구조                        │
├─────────────────────────┬───────────────────────────────┤
│   교육 내용 (What)       │   교육 진행 방식 (How)          │
│   = 각 모듈의 SKILL.md   │   = CLAUDE.md + 전역 규칙      │
├─────────────────────────┼───────────────────────────────┤
│ • 학습 목표              │ • 교육 원칙 → AI 행동 규칙      │
│ • 핵심 개념과 범위        │ • 동적 인터랙션 로직            │
│ • 이해도 검증 기준        │ • 세션 관리 (10~15분)          │
│ • 교차 복습 연결 포인트    │ • 비유 생성 규칙 (직무별 맞춤)   │
│                         │ • 좌절/몰입 감지 및 대응         │
│                         │ • 학습↔탐색 모드 전환 규칙       │
└─────────────────────────┴───────────────────────────────┘
```

What은 엄격하게 고정합니다. "이 모듈에서 반드시 다뤄야 할 개념"과 "학습자가 이해했다고 볼 수 있는 기준"은 변하지 않습니다. 반면 How는 AI에게 자유를 줍니다. 어떤 질문을 던질지, 어떤 비유를 쓸지, 어떤 순서로 설명할지는 학습자의 반응에 따라 AI가 판단합니다.

---

### 1-2. 이해도 검증: "질문"이 아니라 "기준"을 정의

초기 설계(v1)에서는 각 모듈의 이해도를 확인하기 위해 구체적인 질문 문구를 지정했습니다.

> v1: *"Token이란 무엇인가요?"라고 물어보고, 학습자가 ~라고 답하면 통과*

이 방식의 문제는 AI가 대화 흐름을 무시하고 체크리스트를 소화하듯 질문을 던지게 된다는 것이었습니다. v2에서는 접근을 바꿨습니다.

> v2: *학습자가 "Token은 LLM이 텍스트를 처리하는 기본 단위이며, 같은 문장도 모델마다 다르게 쪼갤 수 있다"는 방향의 설명을 할 수 있으면 통과*

구체적 질문은 지정하지 않습니다. **"무엇을 이해해야 하는지"** 와 **"이해했다고 볼 수 있는 답변의 방향"** 만 정의합니다. AI가 학습자의 대화 흐름에 맞춰 질문의 형태, 시점, 표현을 자유롭게 결정하도록 했습니다.

---

### 1-3. 두 가지 학습 모드

모든 학습자가 같은 깊이를 원하지 않습니다. 어떤 사람은 "RAG가 어떻게 작동하는지" 원리를 파고 싶고, 어떤 사람은 "요즘 뭐가 뜨는지" 빠르게 훑고 싶습니다. 이 차이를 무시하면 한쪽은 지루해하고 다른 쪽은 압도당합니다.

이 문제를 해결하기 위해 두 가지 모드를 설계했습니다:

**학습 모드 (Learn Mode)** — 개념을 깊이 있게 이해하는 것이 목표입니다. AI가 소크라테스식으로 질문하고, 이해도를 확인하며, 학습자 맥락에 맞는 비유로 설명합니다. 각 모듈에 정의된 이해 기준을 충족하면 해당 모듈이 완료됩니다.

**탐색 모드 (Explore Mode)** — "요즘 AI에서 무슨 키워드가 뜨는지" 빠르게 훑고 싶은 학습자를 위한 모드입니다. AI가 사전(dictionary)처럼 간결하게 핵심만 설명하고, 관련 개념끼리의 연결을 보여줍니다. 이해도 체크는 하지 않습니다.

핵심은 두 모드가 분리된 별도의 경로가 아니라 **언제든 전환 가능**하다는 점입니다:

```
[탐색 → 학습]
AI: "RAG의 기본 개념은 이렇습니다. [간결한 설명]
     혹시 RAG가 실제로 어떻게 작동하는지까지 깊이 알고 싶으시면
     Module 3에서 자세히 다루고 있어요.

     1) Module 3으로 가서 깊이 배우기
     2) 여기서 계속 다른 키워드 탐색하기"

[학습 → 탐색]
학습 모드 중 "이건 깊이까지는 필요 없고 대충 뭔지만 알면 돼"
→ 해당 개념에 대해서는 탐색 모드처럼 간결하게 설명하고 넘어감
```

---

### 1-4. 동적 인터랙션

학습자의 응답 패턴을 보고 AI가 인터랙션 방식을 자동으로 조절합니다.

학습자가 간결하게 답하는 패턴을 보이면 선택지(번호) 비율을 높이고, 서술형으로 길게 답하는 패턴이면 서술형 질문 비율을 높입니다. 이 규칙을 명시적으로 넣은 이유는, AI가 기본적으로 모든 학습자에게 동일한 형식의 질문을 던지는 경향이 있었기 때문입니다.

---

### 1-5. 세션 관리

10~15분마다 자동으로 세션을 끊고, 지금까지 다룬 내용을 요약한 뒤 다음 선택지를 제시합니다. 학습자가 "이 정도면 됐다"고 느끼는 시점을 놓치지 않게 하기 위한 장치입니다. 한 세션이 너무 길어지면 학습자의 집중력이 떨어지고, AI도 앞선 맥락을 놓치기 시작합니다.

---

### 1-6. 교차 복습

새로운 개념을 설명할 때 이전 모듈에서 배운 개념을 자연스럽게 재등장시킵니다. 별도의 "복습 시간"을 만드는 것이 아니라, 새 개념의 설명 맥락 안에서 이전 개념이 다시 나오도록 설계했습니다.

> 예: Module 3(RAG)에서 "LLM이 답을 생성하는 과정"을 설명할 때,  
> Module 1에서 배운 "확률적 예측"과 Module 2에서 배운 "Context Window"가 자연스럽게 재등장

---

### 설계 원칙 요약

| 원칙 | 적용 방식 |
|:-----|:----------|
| **What은 고정, How는 자유** | 학습 목표와 범위만 정의. 설명 방식·질문·비유는 AI가 학습자에 맞춰 변주 |
| **문제(상황)가 모듈을 이끈다** | 각 모듈은 하나의 해결 가능한 질문으로 시작 |
| **동적 인터랙션** | 학습자 응답 패턴에 따라 선택지↔서술형 비율 자동 조절 |
| **이해 기준만 정의** | 구체적 질문은 지정하지 않음. "이해해야 할 것"과 "통과 기준"만 정의 |
| **교차 복습** | 새 개념 설명 시 이전 모듈의 개념을 자연스럽게 재등장 |
| **10~15분 세션 단위** | 자동 세션 끊기 + 요약 + 선택지 제시 |
| **개인정보 최소화** | 이름 묻지 않음. 직무/직급/도구 경험만 파악 |
| **ASCII 시각 자료** | 파일 생성 없이 터미널 내 다이어그램/표/흐름도 |
| **두 가지 학습 모드** | 깊이 있는 학습 모드 + 트렌드/키워드 탐색 모드 |

## 2. 진단 대화 설계

---

### 2-1. 왜 진단이 필요한가

AI 튜터는 학습자를 처음 만나는 순간 아무것도 모릅니다. 이 상태에서 Module 1부터 일괄적으로 시작하면, 이미 아는 내용을 반복하거나 너무 어려운 지점에서 시작하게 됩니다. 진단 대화는 교육 시작 전 최소한의 질문으로 학습자 프로필을 만들어, AI가 이후 모든 대화에서 참고할 수 있도록 하는 장치입니다.

---

### 2-2. 설계 제약조건

진단 대화를 설계할 때 스스로 부과한 제약조건이 있습니다:

- **번호 선택 방식만 사용** — 서술형 답변을 요구하면 학습자가 부담을 느끼고, AI가 자유 텍스트를 해석하는 과정에서 오류가 생깁니다
- **5문항 이내** — 진단 자체가 길어지면 학습 시작 전에 이탈합니다
- **개인정보 최소화** — 이름을 묻지 않습니다. 교육에 필요한 것은 직무 맥락과 경험 수준이지 개인 식별 정보가 아닙니다

---

### 2-3. 5가지 진단 질문과 설계 의도

각 질문에는 명확한 활용 목적이 있습니다. "물어보면 좋을 것 같아서"가 아니라, 이후 AI의 행동을 구체적으로 어떻게 바꾸는지가 정의되어 있습니다.

---

**질문 1 — 직무**

```
현재 직무가 어디에 가장 가까운가요?

  1) 데이터 엔지니어링 (파이프라인, ETL, 인프라)
  2) 데이터 분석 (대시보드, 리포트, 인사이트)
  3) PM / 기획 (제품 기획, 프로젝트 관리)
  4) 개발 (백엔드, 프론트엔드 등)
  5) 기타
```

**활용**: AI가 사용하는 비유와 예시의 맥락을 결정합니다. 같은 "RAG" 개념을 설명하더라도, 엔지니어에게는 파이프라인 비유를, 분석가에게는 쿼리 비유를, PM에게는 고객 시나리오를 사용합니다.

---

**질문 2 — 직급 범위**

```
경력 수준은 어느 정도인가요?

  1) 주니어 (1~3년차)
  2) 미들 (4~7년차)
  3) 시니어 (8년차 이상)
  4) 리드 / 매니저
```

**활용**: 설명의 추상화 수준과 전략적 관점의 비중을 조절합니다. 주니어~미들에게는 개별 개념 이해와 실무 사례를 강조하고, 시니어~리드에게는 아키텍처 수준의 이해와 팀 전략·의사결정·ROI 관점을 추가합니다.

---

**질문 3 — AI 경험 수준**

```
AI 도구를 업무에서 어느 정도 사용하고 계신가요?

  1) 거의 안 써봤다
  2) ChatGPT 등을 가끔 써본다
  3) 업무에 꽤 자주 활용하고 있다
  4) AI 도구 여러 개를 비교하며 쓰고 있다
```

**활용**: 모듈 진행 속도와 깊이를 조절합니다. 1~2를 선택한 학습자에게는 기초부터 천천히, 3~4를 선택한 학습자에게는 기초를 빠르게 넘기고 심화에 시간을 투자합니다.

---

**질문 4 — 사전 지식 체크**

```
다음 중 "대략 무슨 뜻인지" 알고 있는 것을 모두 골라주세요.
(모르는 게 있어도 전혀 괜찮습니다!)

  1) Token
  2) RAG
  3) Fine-tuning
  4) Agent
  5) 하나도 모르겠다
```

**활용**: 어느 모듈부터 시작할지, 어떤 개념을 빠르게 넘어갈지 판단합니다. 이 질문의 키워드 4개는 각각 Module 1~4의 핵심 개념에 대응합니다.

---

**질문 5 — 학습 목적**

```
이 교육에서 가장 원하는 것은?

  1) AI 기술의 기본 개념을 이해하고 싶다
  2) 당장 업무에 AI 도구를 활용하고 싶다
  3) 팀에 AI 도입 전략을 세우고 싶다
  4) 요즘 AI 트렌드가 뭔지 빠르게 파악하고 싶다
```

**활용**: 학습 모드(학습/탐색) 추천과 전체 교육의 강조점을 결정합니다. 1~3은 학습 모드를, 4는 탐색 모드를 우선 추천합니다. 3을 선택한 학습자에게는 Module 6(팀 전략)의 비중을 높입니다.

---

### 2-4. 진단 결과 → AI 조절 규칙

5가지 질문의 답변 조합에 따라 AI의 행동이 구체적으로 달라집니다:

```
[직무] → 비유/예시의 맥락 결정
  엔지니어링  → 파이프라인·ETL·인프라 비유
  분석        → 대시보드·쿼리·지표 비유
  PM / 기획   → 제품·고객·비즈니스 비유
  개발        → 코드·아키텍처·API 비유

[직급 범위] → 설명의 추상화 수준 결정
  주니어·미들  → 개별 개념 이해 중심, 실무 사례 강조
  시니어       → 개념 간 관계와 아키텍처 수준
  리드·매니저  → 팀 전략·의사결정·ROI 관점 추가

[AI 경험 수준] → 진행 속도 결정
  낮음 (1~2)  → 기초부터, 속도 천천히
  높음 (3~4)  → 기초 빠르게, 심화에 시간 투자

[사전 지식] → 시작점 결정
  0~1개 선택  → Module 1부터 순서대로
  2~3개 선택  → 해당 모듈 빠르게 복습 후 넘어감
  4개 전부    → Module 5~6 중심, 나머지는 탐색 모드

[학습 목적] → 모드와 강조점 결정
  개념 이해   → 학습 모드 추천
  트렌드 파악 → 탐색 모드 추천
  팀 전략    → Module 6 강조
```

### 2-5. 진단 흐름 전체 구조

```
학습자: /start
         │
         ▼
  ┌─────────────────┐
```

| `explore/SKILL.md` | 탐색 모드 규칙 및 키워드 맵 | How |

## 5. 설계 진화 (v1 → v2)

이 프로그램은 초기 설계에서 여러 차례 검토와 개선을 거쳤습니다. 주요 변경 사항입니다:

| 항목 | v1 (초기) | v2 (현재) |
|:-----|:----------|:----------|
| **교육 철학** | 없음 | 6가지 원칙 수립 |
| **구조** | 용어 카테고리별 나열 | 스토리라인 기반 연결 |
| **출력물** | 용어 사전 중심 | 개념 지도 + 세션별 스토리라인 + 토론 질문 |
| **학습자 경험** | 수동적 지식 습득 | 질문을 통해 스스로 발견하는 경험 |
| **이해도 검증** | 구체적 질문 문구 지정 | "이해해야 할 것"과 "통과 기준"만 정의 |
| **학습 모드** | 단일 모드 | 학습 모드 + 탐색 모드 (자유 전환) |
| **규칙 관리** | 각 모듈에 중복 작성 | What/How 분리 (CLAUDE.md가 How를 전역 관리) |
